# Quest Meals OS: build plan

This is the contract every subagent builds against. When reality differs, update this file in the same commit.

## 2. Conventions

- Money: integer birr everywhere in storage and between functions (`*_birr` columns, `...Birr` fields). Intermediate pricing maths may use floats; round only where the formula says.
- Quantities in storage: integer grams for mass items, integer pieces for piece items (eggs, egg whites, injera). Base recipe amounts are `numeric(8,1)` grams because the spec has 13.5 g oil; profile portions (what the kitchen cooks) are integers.
- Body weight: integer grams (`weight_g`). Height: integer cm.
- Dates: business dates are `date` columns as `YYYY-MM-DD` strings in Addis time. Instants are `timestamptz` (UTC). Convert only with `src/domain/time.ts`.
- Weeks start Monday (ISO). `week_start` is always a Monday date string.
- Every service function signature: `async function name(ctx: Ctx, input: T): Promise<R>`; first line authorizes; inputs parsed with Zod in the action/route layer and again trusted only for shape.
- Audit: prices, settings, nutrition targets, discounts, payment confirmations, moderation actions -> `audit_log` row (actor, action, entity, entity_id, before, after, reason).

## 3. Database schema

All tables: `id uuid primary key default gen_random_uuid()`, `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()` unless noted. Demo rows carry `is_demo boolean not null default false` on: user, clients, subscriptions, invoices, payments, weekly_orders (cascade), checkins, community_posts, partner_contributions, purchases, stock_counts.

Authz API (`src/server/authz/index.ts`):
```ts
type Role = 'owner'|'operations'|'nutritionist'|'kitchen'|'delivery'|'coach'|'client';
type Actor = { userId: string; roles: Role[]; clientId: string | null; name: string };

assertOwnClient(actor: Actor, clientId: string): void  // staff with clients.read pass; client must match actor.clientId
class ForbiddenError extends Error {}
PERMISSIONS: Record<Permission, Role[]>   // single source of truth, mirrors the table above
// also: PUBLIC_PERMISSIONS (anon), assertClientAccess (= assertOwnClient), assertCanForClient(actor, clientId, staffPerm, ownPerm),
// canUpdateDrop(actor, drop, today), isStaff, hasRole, homePathFor(roles), loadActor(db, userId)
```

Permission names are the keys of `PERMISSIONS` in `src/server/authz/index.ts` (e.g. `clients.readOwn`, `swaps.approve`, `orders.lock`, `delivery.update`, `community.coach`); `*Own` permissions must be paired with `assertClientAccess` / `assertCanForClient`.

## 7. Domain rules decided here (also in DECISIONS.md)

- Cook date = drop date. Daily and three-drops: each service day is its own cook day. Sunday's meals (when Sunday is not a service day and `sundayWithSaturday` is on) are cooked and dropped Saturday. Every-3-days: drops group up to 3 consecutive meal dates. Weekly delivery stays a pricing option but no package offers it and it cannot be enabled while the freshness rule is 3 days.
- Quick start: start = next service day after the quick-start lock (today 18:00 if paid by then). Period runs from start to the Sunday before the first week that a weekly cutoff strictly after the client's lock will lock (a weekly lock at the same instant does not include them), so the client never falls between a lock they missed and the cycle (Monday sign-up -> this Sunday; Friday -> end of next week; D017, D104). Amount = price_day × service days in period, nearest 10. Capacity per start date (default 5); if full, the next date with room.
- Weekly lock covers week W+1 at Thursday 18:00 of W. A day is cooked only if it is covered by a paid invoice; a week with no covered days is `skipped_unpaid`. Paused week -> `paused`.
- Billing: weekly invoices cover Monday–Sunday weeks; monthly invoices cover calendar months from the start date. Both are generated at the Thursday lock for the period starting in the week after next, due at that period's cutoff. Amount for a full month = plan_price − discount; for any other period = round10((plan_price − discount) × service days ÷ 26).
- Subscription term: default 1 month, options 1–4 months; price locked 4 months from start; renew = extend end_date by the term.
